# VideoMind R5 execution budget

The production Agent budget remains **50,000 cumulative model tokens** by default. This is a per-task ledger across worker deliveries and model retries. A retry does not start a fresh budget. The zero cost cap means cost enforcement is disabled; the token cap still applies. R5 changes the Agent execution deadline from 120 to 240 seconds after a real 89-second Executor response and a separate Critic repair path exhausted the prior deadline despite consuming fewer than 25,000 tokens. This gives normal model latency and one bounded repair room without changing the token cap or provider timeout. The R4 acceptance script must run without a local budget override.

## Call graph and context ownership

| Call                                      | Purpose                                                         | Model-facing context                                                                               | Output reserve (tokens) |
| ----------------------------------------- | --------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- | ----------------------: |
| `CHUNK_SUMMARY`                           | Summarize each chunk; bounded fallback may split a failed chunk | Exact 60-second window text and times                                                              |                   4,096 |
| `RETRIEVAL_PLANNER`                       | Turn the goal into a search intent                              | Goal and retrieval instructions                                                                    |                   1,024 |
| `PLANNER`, `PLANNER_REPAIR`, `REPLANNER`  | Produce or repair ordered tasks                                 | Goal and coarse temporal windows                                                                   |                   2,048 |
| `EXECUTOR`, tool turns, `EXECUTOR_REPAIR` | Generate answer, call tools, or repair DTO shape                | Plan plus selected exact source lines; structural repair gets only the invalid output and contract |                   8,192 |
| `CRITIC`                                  | Check coverage, structure, claims, timestamps and evidence      | Plan, draft, selected exact source lines and binding contract                                      |                  16,000 |
| `CRITIC_REPAIR`                           | Repair invalid Critic JSON without reassessing it               | Invalid Critic output and DTO contract only                                                        |                   8,192 |

The static reserve values are admission estimates based on the representative 346.19-second media run, including hidden reasoning tokens. They are **not** transport `max_tokens` caps. Actual provider usage is checked again as soon as each call returns. A single unexpectedly long provider response can still exceed the cap; the task then terminates explicitly at that call boundary. Changing frozen model-profile output limits is outside R5.

Planner receives a coarse window projection (`startMs`, `endMs`, `transcript`, `ocrTexts`) for whole-video coverage. Executor and Critic receive item-level `sourceItems` (`source`, `startMs`, `endMs`, `text`) so excerpts can bind to one authoritative ASR/OCR observation. This projection excludes repeated checkpoint identities, digests, frame refs, path metadata and original observation copies. Source identity and provenance remain in the durable `VideoContext`; the deterministic Evidence Guard binds and verifies them after model generation. When a segment has no usable source items, the prompt falls back to the exact window text instead of dropping evidence. The summarizer uses coarse windows. Retrieval selects context through the existing application service; R5 adds no arbitrary first-N truncation or mode labels.

The Critic remains a real semantic call. It receives the draft and selected source lines, with an explicit compact CriticResult field/type contract. The prompt also requires empty issue arrays for a passing verdict: a positive sentence in `feedback` otherwise forces an unnecessary rewrite under the conservative deterministic guard. The application applies unchanged structure checks plus strengthened provenance checks: with authoritative source items present, a passing Critic also requires every answer evidence item to bind to a verified item. The public citation view uses the same bound evidence. A structurally invalid Critic DTO gets one context-free repair call only when its original verdict is an explicit parseable boolean; the repair cannot change that verdict or discard issue-list entries. Semantic failures still use the Agent loop's evidence refresh or rewrite path, not DTO repair.

## Accounting and admission

Before each HTTP attempt, the chat transport asks `R4AgentTelemetry` to admit that exact request. It estimates system and user message input from UTF-8 byte length, adds the stage output reserve, and compares the sum with remaining cumulative tokens. The trace records `modelCallAdmission` with stage, model, attempt, Agent round, reason, input estimate, reserve, prior cumulative usage, remaining budget and decision. It records counts only; no prompt or media text is stored in this diagnostic.

When the provider reports token usage, that count is authoritative for both the cumulative ledger and the stage report. Pre-call estimates are never added to reported counts. Provider cost, when returned, is charged once and retained separately. If a sent request lacks token usage, the client records a labelled `heuristic` estimate from the admitted input and visible response size; a failed transient attempt is charged before its next admission. A cost-only provider response retains its reported cost while labelling its token count `heuristic_tokens_provider_cost`. These token values are estimates, not claimed provider facts. `modelCallUsage` records actual or heuristic input/output/total, cumulative usage and remaining budget. The existing Redis trace retains up to 128 bounded response diagnostics, including transport, structured-output and routing diagnostics. Role counters, latency observations and response diagnostics share that trace.

Budget exhaustion propagates through summary and retrieval fallbacks, is treated as a permanent business outcome for this attempt, and is published as `BUDGET_EXHAUSTED` with a concise Chinese message. It is never silently presented as a successful summary fallback or repeated as another worker business attempt. The recoverable failure handoff remains durable. Provider transient retries remain bounded by the provider settings and each retry has a fresh admission decision. Deterministic DTO failures use one targeted repair where supported; evidence or major content failures still require semantic regeneration.

## Measured baseline and prompt forensics

On media 25, the pre-R5 normal-default run completed after consuming **64,243 provider-reported tokens** and provider-reported cost **0.016812324**. The old budget guard ran after major stages and could not stop the final Critic call before overshoot. Its six calls were: chunk summary 14,735, retrieval planner 265, Planner 13,429, Executor 16,472, Critic 19,342 tokens. The three Agent roles alone received 41,294 input tokens. The checkpoint's old model-facing `VideoContext` serialization was 28,844 characters for the representative media, while its transcript text was only 2,783 characters. Source identities and repeated metadata accounted for much of the difference. The coarse projection is 3,197 characters; the item-level projection is about 6,112 characters for 53 observations. Both retain time and exact text. These are prompt payload sizes, not provider token counts.

The first compact-context candidate (media 27) consumed 20,644 tokens but produced zero bound public citations despite passing the model Critic. It is a rejected quality result. R5 therefore supplies exact item-level source lines to Executor/Critic and makes provenance binding a deterministic pass condition. A lower token count alone is not an acceptance result.

Two final-code normal-default acceptance runs passed with verified citations: media 34 used 27,403 provider-reported tokens, cost 0.0178752, five citations and one business attempt; media 35 used 22,719 tokens, cost 0.012775366, four citations and two business attempts after one transient embedding failure. The second attempt repeated two chunk summaries because the first attempt could not persist a complete vectorized chunk set. The final-code token reduction against media 25 was 57.3% and 64.6%, respectively. Provider reasoning output dominated the cost variation: the first final Critic used 14,734 output tokens and took about 89 seconds, while the second used 4,280 output tokens and took about 29 seconds. These two successes demonstrate the default-budget path but do not establish deterministic provider latency or cost.

## Reading one trace

Filter `responseDiagnostics` by `kind=modelCallAdmission` and `kind=modelCallUsage`, then group by `stage`, `round`, `reason` and `attempt`. `chatUsage` shows provider token split and provider-reported cost when present. `modelCalls` and stage counters show call counts; `*LatencyMs` values are stage observations, not a sum of task wall time. `estimatedTokens` is the cumulative budget ledger; its historical name is retained for compatibility even when its value is provider reported. Compare a denied admission with `modelBudgetDenials`; compare a post-call provider overshoot with `modelBudgetOverruns`. `usageSource` distinguishes reported from heuristic numbers.

The input estimator is a conservative planning heuristic for ordinary prose, not a tokenizer or a formal upper bound for arbitrary content. The output reserve is based on measured stages and does not force the provider to stop at that size. A provider that omits usage leaves only a labelled estimate. Cost admission checks the current accumulated cost because this transport does not have a reliable pre-call price quote. The 240-second deadline remains a finite execution bound; a slow provider can still exhaust it. These limitations are explicit so engineers do not mistake a predicted reserve for a guaranteed provider bill or context window.

## Operating decision

Keep the default at 50,000 tokens. Do not set 100,000 for routine acceptance. Watch real `modelCallUsage` and public citation counts together on long videos. For any budget failure, inspect the last admitted/denied stage and preceding repair/rewrite calls before considering a budget-policy change. The 53-item sample produces a 6,112-character fine evidence projection; holding content density and selection breadth constant, ten times as many selected items would produce roughly 61,000 characters before role instructions and drafts. That is a size scenario, not a multi-hour token or cost forecast. Retrieval breadth, OCR density, provider reasoning output and Agent rounds can change the result substantially; broad global tasks still need coverage-aware hierarchy.
